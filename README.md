## 1. Постановка задачи

### 1.1. Что делается

Разрабатывается **абстрактный тип данных ?бинарное дерево?** ? иерархическая динамическая структура, каждый узел которой хранит значение произвольного типа и ссылки не более чем на двух потомков (левого и правого). Структура поддерживает:

- хранение и модификацию связей (установка корня, левого/правого потомка, вставка, очистка);
- обходы в шести порядках, задаваемых перестановкой ?Корень ? Лево ? Право?;
- функциональные преобразования над содержимым (map, where, reduce, слияние);
- извлечение поддерева, поиск поддерева, поиск элемента, поиск узла по пути;
- сериализацию в строку и восстановление из строки в соответствии с заданным обходом.

Реализация выполнена в парадигме ООП с использованием обобщённого программирования (шаблоны/дженерики), чтобы структура работала с произвольным типом элементов при условии, что для него определены операции сравнения и, при необходимости, потокового вывода. Некорректные входные данные (пустое дерево, отсутствующий элемент, неверный путь, неверный формат строки) обрабатываются через механизм исключений.

### 1.2. Зачем это нужно

Бинарное дерево ? базовая структура для понимания ассоциативных контейнеров (словарей, множеств), построения деревьев поиска, синтаксических деревьев, кучевых структур. Работа демонстрирует:

- владение указательными динамическими структурами и ручным управлением памятью (в терминах языка ? владение/освобождение ресурсов);
- применение ООП и обобщённого программирования;
- проектирование API контейнера с богатым набором операций (обходы, преобразования, сериализация);
- покрытие алгоритмов модульными тестами и визуализацию структуры через пользовательский интерфейс.

### 3.3. Описание компонентов, ключевых алгоритмов и решений

**Ядро структуры.**

- **Владение.** Дерево владеет узлами; при копировании выполняется глубокое клонирование поддерева, при перемещении ресурсы передаются с обнулением источника, при уничтожении/очистке поддерево удаляется рекурсивно с корректным обновлением размера.
- **Вставка.** Итеративная: сравнение с текущим узлом, спуск влево при меньшем значении, вправо ? при большем или равном. Дубликаты разрешены (структура не является деревом поиска в строгом смысле), поэтому между дубликатами могут стоять другие элементы. Итеративность выбрана как защита от переполнения стека на вырожденных деревьях.
- **Обходы.** Рекурсивная реализация для всех шести порядков; каждый обход параметризуется перечислением. Обход используется как основа для `traverse` (сбор значений в вектор), `visit` (применение функции к значениям), `reduce` (свёртка), `collectPtrs` (сбор указателей на узлы).
- **Преобразования.**
  - `map`: строит новое дерево той же формы, применяя функцию к каждому значению; тип результата может отличаться от исходного.
  - `where`: строит новое дерево из узлов, удовлетворяющих предикату; при удалении узла его поддеревья переподвешиваются так, чтобы не потерять потомков.
  - `reduce`: свёртка в аккумулятор в заданном порядке обхода.
  - `merge`: поэлементное слияние двух деревьев с помощью функции-комбинатора в заданном порядке, затем пересборка в сбалансированное дерево.
- **Поиск и извлечение.** `contains` ? поиск значения; `extractSubtree` ? клонирование поддерева с первым (в порядке КЛП) узлом с заданным значением; `containsSubtree` ? рекурсивное сравнение поддеревьев; `findByPath` ? проход по строке L/R с выбросом исключения при неверном пути.
- **Сериализация.** `serialize` ? строка значений через пробел в заданном обходе; `deserialize` ? разбор строки и построение сбалансированного дерева (построение из середины отсортированного/заданного набора), с выбросом исключения при ошибке разбора.
- **Особые решения.**
  - `setLeft`/`setRight`/`setRoot` присутствуют для полноты картины бинарного дерева (не только дерева поиска); после замены поддерева размер пересчитывается.
  - Рекурсия используется там, где структура естественно рекурсивна (обходы, клонирование, преобразования); итеративность ? в вставке и (в комментариях) в уничтожении/клонировании как альтернатива.

**Вспомогательная логика.**

- **Узел** ? структура со значением и двумя ссылками; единственный параметрический конструктор.
- **Обход** ? перечисление шести порядков; функции преобразования ?строка ? обход?, ?обход ? строка?, ?обход ? массив перестановки?.
- **Исключения** ? базовый класс `TreeException` (наследник `runtime_error`) и наследники: `EmptyTreeException`, `ElementNotFoundException`, `InvalidFormatException`, `InvalidPathException`. Сообщения содержат контекст операции.

**Тесты.** Консольный класс с набором проверок: вставка и размер, обходы (размер, первый/последний элемент, позиция корня), map, where, reduce, contains/extractSubtree (включая перехват исключений), сериализация/десериализация, findByPath (валидные и невалидные пути), копирование и перемещение. Вывод ? цветной, с итоговой статистикой пройденных/непройденных тестов.

**GUI.** Окно с панелью управления (вставка значения, генерация случайного дерева из 20 элементов, очистка, выбор обхода, обход, сериализация, чтение из строки, поиск по пути, извлечение поддерева, map ?2, where >5), журналом и графической сценой, на которой дерево отображается узлами-эллипсами и соединительными линиями; после каждой операции сцена перерисовывается и масштабируется под содержимое.

## 4. Функциональные требования

Требования сгруппированы по частям системы; для каждой операции указаны особые сценарии.

### 4.1. К дереву в целом

| Требование | Особые сценарии |
|---|---|
| Создание пустого дерева | `empty()` = true, `size()` = 0 |
| Копирование | Глубокое; изменения копии не влияют на оригинал |
| Перемещение | Источник становится пустым |
| Присваивание | Корректно работает и для lvalue, и для rvalue |
| Уничтожение / очистка | Все узлы освобождаются, размер = 0 |
| Запрос состояния | `empty()`, `size()` |
| Вывод в поток | Размер и значения в порядке КЛП |

### 4.2. К узлам и связям

| Требование | Особые сценарии |
|---|---|
| Установить/заменить корень | На пустом дереве создаёт корень, размер = 1 |
| Установить/заменить левого потомка | На пустом дереве ? исключение `EmptyTreeException`; замена освобождает старое поддерево, размер пересчитывается |
| Установить/заменить правого потомка | Аналогично левому |
| Вставить значение | Итеративно; дубликаты разрешены; на пустом дереве создаёт корень |

### 4.3. К обходам

| Требование | Особые сценарии |
|---|---|
| Обойти в заданном порядке и вернуть последовательность значений | Все шесть порядков; пустое дерево ? пустая последовательность |
| Обойти, применив функцию к каждому значению | Функция не должна изменять структуру |
| Свернуть в аккумулятор в заданном порядке | Начальное значение задаётся; пустое дерево возвращает начальное значение |

### 4.4. К преобразованиям

| Требование | Особые сценарии |
|---|---|
| `map`: новое дерево поэлементным преобразованием | Тип результата может отличаться; форма сохраняется; размер сохраняется |
| `where`: новое дерево из узлов, удовлетворяющих предикату | Потомки отфильтрованного узла переподвешиваются, не теряются; размер пересчитывается |
| `merge`: поэлементное слияние двух деревьев | Комбинатор задаётся; порядок обхода параметризуем; результат ? сбалансированное дерево; при разной длине ?хвост? более длинного добавляется |

### 4.5. К поиску и извлечению

| Требование | Особые сценарии |
|---|---|
| Проверить наличие значения | `true`/`false` |
| Извлечь поддерево по значению корня | Первый узел в порядке КЛП; если нет ? `ElementNotFoundException` |
| Проверить вхождение поддерева | Пустое поддерево считается входящим; сравнение рекурсивное |
| Найти значение по пути | Только L/R (регистр не важен); неверный символ или отсутствующий потомок ? `InvalidPathException`; пустое дерево ? `EmptyTreeException` |

### 4.6. К сериализации

| Требование | Особые сценарии |
|---|---|
| Сохранить в строку в заданном обходе | Значения через пробел; пустое дерево ? пустая строка |
| Прочитать из строки в заданном обходе | Неверный формат ? `InvalidFormatException`; пустая строка ? пустое дерево; результат ? сбалансированное дерево |

### 4.7. К тестам и интерфейсу

| Требование | Особые сценарии |
|---|---|
| Модульные тесты основных алгоритмов | Граничные и некорректные значения (пустое дерево, отсутствующий элемент, неверный путь/формат); читаемый вывод; итоговая статистика |
| Консольный/GUI-интерфейс | Ручной и автоматический (случайное дерево) ввод; отображение исходных данных, промежуточных и конечных результатов; визуализация структуры |
| Сборка двух целей | Тесты и GUI собираются независимо, ядро общее |
